# Starlte integration checks

These checks compile and execute production interrupt, loader, reset,
framebuffer and UFS components with explicit test-owned service boundaries. They
run on the host and QEMU `virt`. Full-kernel CI/QEMU observations, Samsung
hardware provenance and device-validation status are recorded in
[`docs/STARLTE.md`](../../docs/STARLTE.md).

## Prerequisites

The recorded environment is Linux/x86_64, Clang **23.1.3** and QEMU
**11.1.2**. Put these executables on `PATH`:

* Python 3 and a host C compiler (`cc`). Run Python without `-O`, since
  the checks use assertions.
* `clang`, `clang++`, `ld.lld`, `ld64.lld`, `llvm-nm`, `llvm-objcopy`, with
  AArch64 ELF and arm64 Mach-O support.
* `qemu-system-aarch64`. Loader/reset guests use **cortex-a76**, which
  supports their 16 KiB translation granule. `cortex-a57` faulted when the
  loader enabled its 16 KiB tables.
* `dtc` for `enxerto.py`; GNU AArch64 GCC/binutils for its `--qemu` build.
  `enxerto/build.sh` detects `aarch64-linux-gnu-` or `aarch64-elf-`, or
  accepts `CROSS=...`.
* `bison`, `flex`, `tcsh`, `unifdef` for `headers.py`. The last two can be
  supplied with `--tcsh /absolute/path` and `--unifdef /absolute/path`.
* Host Clang AddressSanitizer/UndefinedBehaviorSanitizer runtimes and zlib
  headers/library for `ufs.py` (`-lz`).

The XNU checks need a **fully staged and patched** `xnu-12377.121.6` tree,
including patches 1131–1135. Default: `research/starlte/xnu`.
Preparation follows [`xnu.yml`](../../.github/workflows/xnu.yml) /
[`tools/xnu-local-build.sh`](../xnu-local-build.sh):

1. XNU commit `ac9718fb1af618d5ce8678d0dc6e8a58f252216f` and dxb commit
   `663906528d1cd5ea8fde7de6f16de73db9511549`.
2. Run the four `xnu/patches-12377/*.sh` staging scripts from the XNU root
   with `MACHINE_CONFIG=SWEET`, `MACOS_VERSION=26.5`. They stage libpthread,
   BearSSL, HFS and the no-KDK CoreEntitlements fallback. The source staging
   requires `TargetConditionals.h`; a directory containing that header
   alone is not a build SDK.
3. Apply dxb's `patches/26.0/*.patch`, then Bergamota's
   `xnu/patches-12377/*.patch`, in filename order. The only documented dxb
   skips for this source release are `link_kdk.patch` and
   `remove_applefeatures_include.patch`.

The existing prepared tree and its reconstruction evidence are recorded
in `NOTES.md`. Preparation is a fresh-tree operation; preserve that tree
when reproducing the series. Component execution uses synthetic payloads
and requires neither an Apple identity ADT nor an iOS root image.

## Commands

Run from the repository root:

```sh
python3 tools/starlte-check/check.py
python3 tools/starlte-check/enxerto.py --qemu
python3 tools/starlte-check/headers.py
python3 tools/starlte-check/reset.py
python3 tools/starlte-check/ufs.py
```

`enxerto.py` without `--qemu` runs only its host cases. Each script accepts
`--out DIR`; `check.py`, `headers.py`, `reset.py` and `ufs.py` also accept `--xnu DIR`.
`reset.py --headers DIR` and `ufs.py --headers DIR` must point to the configuration generated by
`headers.py --out DIR` for that same XNU tree. It freshly compiles the
complete production `genassym.c` rather than reusing old offsets.

For the extended C++ check, provide Apple's open-source
[`bootstrap_cmds-138`](https://github.com/apple-oss-distributions/bootstrap_cmds/tree/c71d2d72f48995baaea76148f61002e5299841de)
at commit `c71d2d72f48995baaea76148f61002e5299841de`:

```sh
python3 tools/starlte-check/headers.py --cpp --mig-source research/tools/bootstrap_cmds
```

The base command passes its five compiles in the recorded environment.
**The extended command currently exits 1** at the C++ infrastructure
limitations below, after generating all 34 exported Mach headers.

## Outputs and interpreting results

| Command | Default output directory | Main evidence |
| --- | --- | --- |
| `check.py` | `research/starlte/check/` | `summary.json`, compiled ELF/Mach-O objects; per-case `serial.txt`, `regs.txt`, `fb.png`, `qemu.log`, `runner.log` |
| `enxerto.py` | `research/starlte/enxerto-check/` | `host-summary.json`, `compatible-summary.json`, optional `qemu-summary.json` / `display-probe-summary.json`; per-guest commands, reports, RAM, console, registers and framebuffer |
| `headers.py` | `research/starlte/header-check/` | `configure.log`, component Makefiles/headers, `results.json` with source hashes/commands/errors, `*.compile.log`, `genassym.json`; `mig-commands.json` with `--cpp` |
| `reset.py` | `research/starlte/reset-check/` | Consolidated `summary.json`; `layout.json`, `boot-layout.json`, `genassym-command.json`, `symbols.json`, `fixture.json`; per-case commands, reports, tables, registers, framebuffer and `result.json` |
| `ufs.py` | `research/starlte/ufs-check/` | `summary.json` with extraction/source hashes and compile command; `host.log`, generated production include, synthetic GPT fixtures, `adt-summary.json`, real-header object/log |

Commands exit nonzero on failure. Fresh `--out` directories keep rerun
evidence unambiguous; `reset.py` and `ufs.py` additionally record `running`, `failed`
or `pass` in its consolidated summary as each case completes. A framebuffer
snapshot alone is insufficient: the scripts assert register, memory and
interrupt results too. High-address reset cases use sparse guest RAM;
the separate-L1 fixture asks QEMU for a 67 GiB guest address range.

All generated artifacts are under ignored directories by default.
`enxerto.py --qemu` also builds `enxerto/out/starlte/`, ending with the
display-probe configuration. Exact normal/probe Images and ELFs are retained
under the check output's `boot-loader/` and `display-probe-loader/`.

## Coverage and service boundaries

### Interrupts: `check.py`

The guest compiles the actual patched `pexpert/arm/pe_fiq.c` and
`osfmk/arm64/sweet_early.c` to both ELF and Mach-O. `compat.h` and generated
include placeholders supply minimal XNU service declarations for this
freestanding guest; `guest.c`, `start.S` and `link.ld` supply ADT services,
logical CPU IDs, startup, vectors and completion reporting.

GIC MMIO/system registers, exceptions, timers and production PSCI/IPI
helpers execute on QEMU. Four cases cover GICv2/v3 × one/eight CPUs:

* 32 virtual-timer interrupts per CPU and 4/200 SGIs per case (self and
  repeated all-to-all delivery).
* Intentionally permuted logical CPU IDs, GICv2 SGI source-token EOI,
  UP ITARGETSR read-as-zero and spurious acknowledge behavior.
* Exactly one QMP register snapshot for each expected CPU, using explicit
  `cpu-index` selection.
* Host checks for v1/v2 RAM equivalence, 608/1024-byte boot_args, Exynos
  affinities, framebuffer geometry, invalid DEFLATE/overlap rejection and
  rejection of hardware ADTs passed to the QEMU runner.

Its vector code supplies the interrupt dispatch; production `sleh.c`'s
exception prologue, scheduler and `SweetCPU` IOKit lifecycle are outside
this guest. The real-header check below covers compilation without these
guest header adapters.

### Enxerto: `enxerto.py`

Host cases build the complete production `loader.c`, `fdt.c`, `adt.c` and
`inflate.c` as a shared library. `enxerto_host.c` replaces console/UI,
charger and MMU/jump services, capturing the handoff with `setjmp`.
The actual `tools/mkpayload.py` produces payloads from a synthetic Mach-O.

Twelve cases cover sweet/beryllium/starlte × 608/1024-byte boot_args ×
payload v1/v2. Destination RAM begins dirty and payload padding is nonzero.
Assertions check exact initialized bytes, odd-sized data/BSS tails, ADT,
command-line padding, ABI offsets, charger selection, malformed-initrd
rejection before destination writes, parent-specific FDT cell counts
(2/1 and 2/2), and 32/64-bit initrd properties. The host MMU service supplies
synthetic Image/DMA bounds; tests verify the copied ADT's runtime handoff,
an untouched source payload, and rejection of destination/Image overlap.

Twenty-four host cases exercise the root-compatible gate used before Samsung
MMIO: multi-string exact matches, child-only identities, prefixes, different
case, absent/empty lists, invalid block/property bounds and unterminated
strings. This gate recognizes the supplied Samsung template's spelling.

`--qemu` builds and executes the **actual Samsung Enxerto Image**, including
its startup, platform diagnostics, UI, page-table setup and final assembly
handoff. Four cases cover GICv2/v3 × EL1/EL2. A synthetic payload probe
reports entry registers; the host verifies byte-exact kernel/ADT/boot_args
RAM, EL1, masked interrupts and MMU/I-cache/D-cache off. These cases test
loader entry/handoff, with interrupt delivery covered by `check.py`.
The GICv2/EL2 case adds a Samsung UFS node to its synthetic ADT and verifies
the real Image-owned DMA export against ELF symbols and runtime placement.
The payload only records the handoff; it accesses no Samsung UFS registers.

Two further EL1/EL2 cases build `STARLTE_DISPLAY_PROBE=1` and check the held
screen's RGB strip and console, preserved incoming EL, outgoing EL1, and an
untouched dirty payload-destination page. Normal and probe cases capture
the production console's RAM history and verify the non-Exynos skip path.
They execute no Samsung display MMIO: QEMU does not model DECON/IDMA. The
physical trigger/readback path and panel refresh require the device test.

### Real headers: `headers.py`

Native XNU `SETUP/config` and `doconf` generate DEVELOPMENT/ARM64/SWEET/
MacOSX configuration headers for all six components. Five complete
translation units compile against real XNU headers: `genassym.c` to
assembly, and `arm_vm_init.c`, `pe_fiq.c`, `sweet_early.c` and
`KernelConfigTables.cpp` to optimized Mach-O objects.

`--cpp` builds native Apple MIG and generates 34 exported Mach headers
from their actual `.defs`. `mig_host.h` adapts Linux/x86_64 host libc types
only; it is never included by target compiles or `.defs` preprocessing.
Historical `handler.c`, absent from MIG's Xcode Sources phase, is excluded.

Recorded C++ blockers:

* `SweetCPU.cpp`: missing IIG-generated `DriverKit/OSObject.h`.
* `SweetPlatformExpert.cpp`: IOLib template expansion needs Apple-only
  `__builtin_xnu_type_summary`, `__builtin_xnu_type_signature` and
  `__builtin_xnu_types_compatible`; upstream Clang reports `'T' does not
  refer to a value`.

These failures remain visible in logs/results and the command's exit
status. They leave the IOKit drivers' full-build status unresolved; no
target-header substitutes are used to manufacture a passing C++ result.

### UFS transport and DMA ownership: `ufs.py`

`ufs_host.c` is a byte-level UFSHCI/controller/device model. It decodes raw
UTRD/UPIU/PRDT bytes independently of the driver's descriptor structures,
using the pinned Samsung/FMP conventions in `docs/STARLTE.md`. Python creates
synthetic GPT/media fixtures with zlib CRCs. Host execution uses ASan/UBSan
with **`-fno-sanitize-recover=all`**, so a sanitizer finding fails the command.

The runner extracts production transport, retry, capacity, GPT, partition
lookup, initialization, probe and BSD functions. Only six function bodies
are replaced: `ufs_rd`, `ufs_wr`, `exynos_rd`, `exynos_wr`,
`exynos_unipro_rd` and `exynos_fmp_format`. The host adapter supplies MMIO/SMC results, barriers,
time/waits, locks, DMA allocation/mapping, ADT/boot arguments, BSD buffers and
device/peripheral registration. The complete `sweet_ufs.c` is separately
compiled to Mach-O with real DEVELOPMENT/ARM64/SWEET headers and
`BSD_KERNEL_PRIVATE`; extraction hashes are recorded in `summary.json`.

**329 host scenarios** exercise:

* Samsung byte-granular descriptors, 128-byte crypto-bypass PRDs, per-command
  Nexus setup, inherited host/list checks, SMC/setup refusal and DMA bounds.
* The photographed HCE=0 / HCS=0x10f state, already-enabled hosts, all four
  readiness bits, low-byte error/reserved bits, and inherited error status.
  One enable-only attempt requires stopped/idle lists; a 1 ms write-echo guard
  and at most ten 5 ms delays cover immediate/transitional completion, timeout
  and late completion. Readiness/error/list-state loss prevents FMP and commands.
  MMIO write allowlists admit clock/UIC operations only in the explicit startup
  model; device-reset and PHY programming remain excluded.
* The `ufsprobe=1 ufslinkinit=1` startup candidate: HCE independently invalidates
  transport, including a ready-looking HCS case. Local CPort SETs, one
  LINKSTARTUP with Samsung direct UniPro confirmation, connected-lane/CPort
  GETs and a correctly encoded NOP OUT/IN precede SCSI. Already-enabled hosts
  receive GET/NOP checks without LINKSTARTUP. Exact opt-in/mapping, masked
  clock controls before/after HCE, each UIC-stage timeout, frozen-counter poll
  bounds, stale/failed acknowledgements and direct/generic result disagreement
  are exercised. Only the exact PA LINERESET indication accompanying successful
  completed LINKSTARTUP is permitted; other stages/errors and all transfer
  boundaries reject it. Missing/malformed NOP replies, Nexus readback failure,
  pre-NOP readiness loss and late DMA quarantine prevent SCSI. Independent raw
  NOP/TUR bytes select boundary fault injection; tracing extends through NOP to
  verify the original immediate pre-TUR read/doorbell ordering.
* Read-only opcode enforcement even with `ufsrw=1`, timeout-clear polarity,
  late-DMA quarantine, initialization-failure caching, response validation,
  partial-transfer rejection and bounded transient retries.
* First-error and terminal pre-cleanup diagnostics: all seven error bits,
  read-clear layer registers, cleanup-mutated DMA, immediate/delayed completion,
  deadline and doorbell races, raw unknown codes, bounded two-sample output,
  sleepable waits and the photographed TUR failure hold. A later good-looking
  completion cannot hide a previously observed transport error. Samples read
  only the fixed owned UTRD and response header, never media or hardware-provided
  addresses; neither sample validates completion nor adds link recovery.
* The exact Exynos + `ufsprobe=1` pre-submit experiment: independent event
  tracing verifies ten sequential reads after idle/list stop, including
  already-enabled hosts, and immediately before the first TUR doorbell after
  raw 512-byte descriptor/Nexus checks. Sampled IS errors or any nonzero
  layer code stop with EIO, pending DBRs with EBUSY, readiness/pre-TUR HCE loss
  with ENXIO; all quarantine before further setup/submission. Read-cleared
  values remain in RAM. Both two-line records print only at the probe hold,
  never between the final sample and doorbell. Per-boot budgets survive
  retries/LUN scans/repeated logger calls; absent/zero/non-one probe values
  and Qualcomm add no boundary sampling. Earlier rejection suppresses samples.
  A pre-submit failure submits no command, increments no command-failure
  count, and forbids later MMIO/DMA reuse even after synthetic late DMA.
  The test-owned `longjmp` leaves the real nonreturning hold before cached
  `init_error` assignment; later EIO tests cached attempt plus `su.dead`.
* Capacity/block-size validation, READ CAPACITY(16), READ(16) beyond 32-bit
  LBAs, LUNs 0–7, mixed geometries, strict GPT CRC/geometry/partition bounds,
  exact case-insensitive names and mismatched or missing repeated reads.
* Four-byte-aligned ADT data, malformed ownership descriptions, mapping
  failures before MMIO, BSD chunking/residuals/overflow checks, and successful
  or failed probe holds before registration.
* Qualcomm 16-byte PRDs, writable-root verification/RMW, auxiliary lookup,
  legacy name/CRC policy, DMA64 checks, allocation fallback and timeout behavior.

**24 loader cases** execute the complete production `enxerto/adt.c`, checking
the live pool, zero placeholders, malformed/truncated trees, duplicate UFS
nodes, DMA32 alignment/containment, managed-RAM overlap, unchanged non-Samsung
trees and unchanged input/guard bytes on rejection.

These are software protocol/ownership checks. They do not establish Samsung
clock/PHY/link state, secure-firmware acceptance, cache/interconnect behavior,
real DMA access or readable media. Probe 2 physically enabled HCE and observed
the FMP format call returning zero, but its first TEST UNIT READY timed out with
UIC_ERROR. Probe 3 physically recorded first PA `0x80000010`, terminal PA=0,
IS=4/DBR=1/OCS=0x0f before cleanup; cause/timing remain unclassified. The startup
candidate is validated in the `starlte/ufs-link-startup` worktree's
`research/starlte/link-startup-check-1/` and exactly reconstructed in
`research/starlte/series-check-link-startup-retry1/` (279 patches / 6369 files).
The first reconstruction's BearSSL DNS failure is retained separately. These
checks model transport behavior; a candidate CI image and physical result are
still required. Main-checkout probe 4 remains pinned to source `2347574`.

### Reset and final framebuffer: `reset.py`

This suite compiles complete production `start.s`, with offsets from a
fresh compile of complete `genassym.c` and real architectural/`boot.h`
headers. `reset_support.S` supplies the C-service boundaries (`arm_init`,
warm CPU handoffs, table installation and reporting), CPU records/stacks
and exception reporting.

* **Five cold resets:** starlte QEMU RAM; reference S9 upper bank
  `0x880000000 + 0x80000000`; sweet/beryllium framebuffer addresses; and
  synthetic RAM `0x1080000000 + 0x80000000` requiring a separate L1 entry.
  Tables begin filled with `0xa5`. Each case verifies the kernel-VA
  handoff, MMU/boot_args/flags, framebuffer endpoints/stage-0 marker and
  inspected 16 KiB descriptors, with zero exceptions.
* **Four warm cases:** GICv2/v3 × EL1/EL2, eight CPUs each, with four
  `start_cpu` and four `resume_idle_cpu` paths. Logical IDs are permuted;
  CPU records and stacks use real offsets; TTBR1 points to a distinct
  root. A fixture-owned PSCI caller powers on QEMU's seven secondaries.
  EL2 fixtures set `VMPIDR_EL2` to Exynos-shaped affinities while QEMU's
  physical topology remains contiguous. Only the expected PSCI calls and
  EL2 returns appear in exception logs.
* **Three final-framebuffer cases:** starlte/sweet/beryllium execute actual
  `sweet_early_map_final()`, `phystokv()` and `sweet_early_relocate()` from
  complete production `arm_vm_init.c` / `sweet_early.c`, with real headers
  and assertions. The old framebuffer VA faults after TTBR0 teardown;
  the final alias translates and endpoint writes/stages 8/9/10 match.
  The allocator, final root and TTBR transitions are fixture-owned, so
  this exercises the helpers rather than the complete `arm_vm_init()`.

The Mach-O fixture is linked at zero, its VAs shifted to
`0xfffffff008000000`, and `LC_MAIN` replaced with `LC_UNIXTHREAD`. Reset-only
images are checked to have zero chained rebases. The final framebuffer
fixture has 102 image-relative rebases resolved by production `mkpayload`.
Only `__BOOTDATA,__static_if` live-support metadata is removed to permit
dead stripping of unrelated VM services; text bytes are checked unchanged.

The recorded consolidated result is **12/12 PASS**. Samsung secure
interrupt ownership, real timer routing, cache coherency, DECON refresh
and IOKit startup still require full-kernel/device evidence.
